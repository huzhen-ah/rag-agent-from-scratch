# 家电故障诊断评测

本目录用于比较家电故障知识库的四个检索阶段：

```text
Dense
BM25
Dense + BM25 + RRF
Dense + BM25 + RRF + Reranker
```

## 评测数据

`data/appliance_retrieval_eval.jsonl` 包含 159 个问题，由 53 条测试集文档分别生成三种查询：

- `code_lookup`：品牌、家电类型和故障码查询，共 53 条。
- `symptom_lookup`：品牌、家电类型和故障现象查询，共 53 条。
- `code_and_symptom`：故障码与故障现象组合查询，共 53 条。

每条数据只保留评测必需字段：

```json
{
  "retrieve_id": 1,
  "question": "Beko洗衣机显示E03，是什么意思？",
  "query_type": "code_lookup",
  "relevant_chunk_ids": [2]
}
```

## 评测指标

- `Recall@1/3/5`：前 K 个结果召回的相关文档比例。
- `MRR@1/3/5`：每个问题第一个相关文档排名的倒数，再对全部问题取平均。
- `nDCG@1/3/5`：每个问题前 K 个结果的排序质量经过理想排序归一化后，再对全部问题取平均。

四个阶段虽然内部候选数量不同，但评测时使用相同的 Top-K 截断位置。

## 结论

- RRF取得最佳总体结果：Recall@1 为 0.9481，MRR@5 为 0.9858，nDCG@5 为 0.9889。
- Dense明显优于BM25，说明语义表示对自然语言故障现象更有效。
- Reranker提升了症状查询的首位命中和排序质量，但降低了故障码及混合查询的指标，因此当前模型没有带来总体增益。
- 三类查询的 Recall@5 均接近或达到 1.0，主要差异集中在正确文档能否排到第一位。

该评测集由规则模板生成，适合进行检索阶段对比和回归验证，不等同于真实用户问题分布。

## 运行


再运行评测：

```bash
cd evaluation
python evaluate_retrieval.py
```

## Agent工具调用评测

为控制本地模型评测耗时，当前只评测一个最基础场景：用户已经提供完整的品牌、家电类型和故障代码时，Agent是否调用`query_rag`。暂不评测信息缺失追问、多轮上下文融合、工具参数质量和最终回答质量。

评测集`data/appliance_agent_eval.jsonl`包含10条单轮问题，每条样本使用独立的`thread_id`，避免历史消息互相干扰。

唯一指标为：

```text
query_rag调用率 = 调用query_rag的样本数 / 总样本数
```

|---:|---:|---:|
| 10 | 10 | **1.0000** |

运行方式：

```bash
cd evaluation
python evaluate_agent.py
```
